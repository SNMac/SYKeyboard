# 한글 입력 로직

나랏글/천지인/두벌식 세 입력기의 조합, 삭제, 스페이스, 종성 복원, 버퍼 관리를 정리한다.
관련 문서: [전체 아키텍처](전체%20아키텍처.md) · [자동완성 로직](자동완성%20로직.md) · [삭제와 실행취소 로직](삭제와%20실행취소%20로직.md) · [한영 통합 키보드](한영%20통합%20키보드.md)

## 1. 전체 아키텍처

```
사용자 터치
    ↓
BaseKeyboardViewController               (버튼 이벤트 라우팅, proxy 래핑: insertText/deleteText/replaceText)
    ↓
HangeulKeyboardCoreViewController        (버튼 이벤트 → Adapter 호출, Transition 적용만 담당)
    ↓
HangeulKeyboardInputAdapter              (VC ↔ Domain의 유일한 경계. processor/뷰 선택, 조합 상태 보유)
    ↓
HangeulCompositionState (struct)         (committedBuffer/composingBuffer/보호 상태의 실제 소유자)
    ↓
HangeulProcessable                       (프로세서 프로토콜)
    ├── inputWithRestore종성() / deleteWithRestore종성()   ← 프로토콜 기본 구현 (committed와의 종성 복원)
    └── input() / delete() / inputSpace()                  ← 각 프로세서 고유 로직
    ↓
HangeulAutomata                          (표준 한글 오토마타: 자소 합치기/분해, 유니코드 연산)
```

핵심 원칙:

- **조합 계산과 화면 반영이 분리**되어 있다. `HangeulCompositionState`가 버퍼를 갱신하며 proxy 편집 명령
  (`HangeulCompositionTransition`)을 반환하고, VC의 `applyCompositionTransition(_:)`이 그 명령을
  Base의 래핑 메서드(`insertText`/`deleteText`/`replaceText`)로 실행만 한다.
- 래핑 메서드를 거치므로 자동완성의 `inputBuffer`에는 항상 **조합 완료된 문자열**이 들어간다. 자소 단위 중간 상태는 보이지 않는다.
- **종성 복원은 프로토콜 기본 구현에서 공통 처리**한다. 각 프로세서는 `input()`/`delete()`/`inputSpace()`만 구현한다.
- State는 `input()`이 아닌 `inputWithRestore종성()`을, `delete()`가 아닌 `deleteWithRestore종성()`을 호출한다.

주요 파일:

| 파일 | 역할 |
|---|---|
| `Modules/HangeulKeyboardCore/Presentation/ViewController/HangeulKeyboardCoreViewController.swift` | 버튼 이벤트 오버라이드, Transition 적용 |
| `Modules/HangeulKeyboardCore/Presentation/Input/HangeulKeyboardInputAdapter.swift` | processor/키보드 뷰 선택, State 위임, 스페이스 버튼 이미지·Shift 상태 |
| `Modules/HangeulKeyboardCore/Domain/HangeulCompositionState.swift` | 버퍼·보호 상태·삭제 팬 상태, `HangeulProxyEdit`/`HangeulCompositionTransition` |
| `Modules/HangeulKeyboardCore/Domain/Processor/Protocols/HangeulProcessable.swift` | 프로토콜 + 종성 복원 기본 구현, `CompositionResult`/`DeleteResult`/`SpaceInputResult` |
| `Modules/HangeulKeyboardCore/Domain/Processor/{Naratgeul,Cheonjiin,Dubeolsik}Processor.swift` | 입력기별 고유 로직 |
| `Modules/HangeulKeyboardCore/Domain/Automata/HangeulAutomata.swift` | 표준 자소 합치기/분해 |

한영 통합 키보드(`HangeulEnglishKeyboardViewController`)는 Core VC 없이 `HangeulKeyboardInputAdapter`를 직접 들고
같은 방식으로 Transition을 적용한다. → [한영 통합 키보드](한영%20통합%20키보드.md)

## 2. 두 개의 버퍼 구조 (O(1) 설계)

`HangeulCompositionState`가 두 버퍼를 소유한다.

```
committedBuffer: "안녕하"    ← 확정된 텍스트, proxy에서 건드리지 않음
composingBuffer: "세"        ← 현재 조합 중, proxy에서 delete→reinsert 대상 (항상 최대 1~2글자)
```

화면에 보이는 텍스트: `"안녕하세"` (`state.text = committedBuffer + composingBuffer`)

입력할 때마다 composingBuffer(1~2글자)만 지우고 다시 쓰므로, 전체 텍스트 길이와 무관하게 항상 **O(1)** 성능을 보장한다.

## 3. 공통 타입 정의

### CompositionResult — 프로세서 입력 결과

```swift
struct CompositionResult {
    let committed: String              // 확정된 부분 → committedBuffer에 추가
    let composing: String              // 조합 중인 부분 → composingBuffer를 교체
    let input글자: String?             // 반복 입력(길게 누르기)용 마지막 글자. nil이면 반복 불가
    let consumedCommittedCount: Int    // 프로세서가 committedTail에서 소비한 글자 수 (0, 1, 또는 2)
}
```

| 상태 | 입력 | committed | composing | consumed | 설명 |
|---|---|---|---|---|---|
| `"간"` | `"ㅏ"` | `"가"` | `"나"` | 0 | 연음 |
| committed `"가"` + composing `"ㄴ"` 변환 결과 | | `""` | `"간"` | 1 | 종성 복원 (committed `"가"` 소비) |
| `"가"` | `"1"` | `"가1"` | `""` | 0 | 비한글 확정 |

편의 생성자: `.composingOnly("한")`, `.commitAll("가1")`.

### DeleteResult — 프로세서 삭제 결과

```swift
struct DeleteResult {
    let composing: String              // 삭제 후 남은 조합 문자열
    let consumedCommittedCount: Int    // committedTail에서 소비한 글자 수 (0, 1, 또는 2)
}
```

| composing / committedTail | 결과 composing | consumed | 설명 |
|---|---|---|---|
| `"ㄴ"` / `"가"` | `"간"` | 1 | 종성 복원 |
| `"ㄷ"` / `"간ㆍ"` | `"간ㆍㄷ"` | 2 | 천지인 비표준 모음 연음 |
| `"간"` / `"가"` | `"가"` | 0 | 일반 삭제 |

### SpaceInputResult

```swift
enum SpaceInputResult {
    case insertSpace        // 실제 공백 " " 입력 (두벌식/나랏글, 그리고 천지인의 조합 대기 상태)
    case commitCombination  // 조합만 끊고 공백 없음 (천지인의 조합 중 상태)
}
```

### HangeulProxyEdit / HangeulCompositionTransition — 상태 전이의 출력

```swift
enum HangeulProxyEdit: Equatable {
    case none
    case insert(String)
    case delete(count: Int)
    case replace(deleteCount: Int, insertText: String)
}

struct HangeulCompositionTransition: Equatable {
    let proxyEdits: [HangeulProxyEdit]      // 순서대로 실행할 편집 명령
    var proxyEdit: HangeulProxyEdit          // 마지막 명령 (단일 명령 케이스용 편의 접근)
}
```

VC의 `applyCompositionTransition(_:)`은 명령을 순서대로 실행한다:
`.insert` → `insertText`, `.delete(1)` → `deleteText()`, `.delete(n)`/`.replace` → `replaceText(deleteCount:insert:)`.
`.none`은 아무것도 하지 않는다(버퍼만 바뀐 경우, 예: 천지인 조합 확정 스페이스).

## 4. 프로토콜 기본 구현 — 종성 복원

`HangeulProcessable` extension이 committed와의 종성 합치기를 공통 처리한다.

### 4-1. inputWithRestore종성

각 프로세서의 `input()`을 호출한 뒤 종성 복원을 시도한다.

```
종성 복원 조건 (모두 만족):
1. 이전 composing이 있었음 (변환 결과로 자음이 남은 것)
2. result.committed가 비어있음
3. result.composing이 낱자 자음 1개
4. committedTail이 비어있지 않음
5. isProtected == false (스페이스 확정으로 보호되지 않음)
```

예시 (나랏글):

```
committedTail: "가", composing: "ㅅ"
입력: "획" → processor.input() 결과: committed "", composing "ㅈ"

→ tryMerge종성("ㅈ", committedTail: "가") → automata.add글자 → "갖" (1글자) → 성공
→ 결과: committed "", composing "갖", consumedCommittedCount: 1
→ Transition: .replace(deleteCount: 2, insertText: "갖")   // composing "ㅅ"(1) + 소비된 "가"(1)
→ committedBuffer: "", composingBuffer: "갖"
```

### 4-2. deleteWithRestore종성

각 프로세서의 `delete()`를 호출한 뒤 종성 복원을 시도한다.

```
종성 복원 조건 (모두 만족):
1. 프로세서가 이미 committed를 소비하지 않았음 (consumedCommittedCount == 0)
2. result.composing이 낱자 자음 1개
3. committedTail이 비어있지 않음
4. isProtected == false
```

예시:

```
committedTail: "가", composing: "나"
삭제 → processor.delete() → composing "ㄴ" (모음 삭제)
→ tryMerge종성("ㄴ", "가") → "간" → 성공
→ 결과: composing "간", consumedCommittedCount: 1
→ Transition: .replace(deleteCount: 2, insertText: "간")
→ committedBuffer: "", composingBuffer: "간"
```

### 4-3. tryMerge종성 (공통 private)

낱자 자음 1개를 committedTail의 마지막 한글에 종성으로 합치기를 시도한다.

```
1. 자음이 종성Table에 존재하고 " "가 아닌지 확인
2. committedTail 마지막 글자가 decompose 가능한 완성형 한글인지 확인
3. automata.add글자()로 결합 시도
4. 결과가 1글자이면 성공 (예: "가" + "ㄴ" → "간"), 2글자 이상이면 실패 → nil
```

## 5. HangeulCompositionState — 상태 전이

State는 값 타입(struct)이며 processor를 인자로 받아 동작한다. 모든 public 전이 메서드는 Transition을 반환한다.

### 5-1. 입력: `input(_:using:)`

```swift
mutating func input(_ text: String, using processor: HangeulProcessable) -> HangeulCompositionTransition {
    return applyCompositionResult(
        processor.inputWithRestore종성(
            글자Input: text,
            composing: composingBuffer,
            committedTail: String(committedBuffer.suffix(2)),
            isProtected: committedBuffer.count <= protectedCommittedCount
        )
    )
}
```

### 5-2. 결과 반영: `applyCompositionResult` (private)

두 가지 경로가 있다.

**경로 A — 최적화** (`result.committed == 이전 composing && consumedCommittedCount == 0`):
기존 composing이 그대로 확정된 경우. 이미 화면에 있으므로 지우지 않고 새 composing만 `.insert`한다.

```
예: 천지인에서 is한글조합OnGoing == false일 때 새 자음 입력
composing: "가", 입력: "ㄴ" → 결과: committed "가", composing "ㄴ"
→ "가" == 이전 composing → Transition: .insert("ㄴ")
→ committedBuffer += "가", composingBuffer = "ㄴ"
```

이 경로에서 `isPulledFromProtected == true`이면 `protectedCommittedCount = committedBuffer.count`로 보호를 복원한다.

**경로 B — 일반 경로**: 기존 composing 전체 + 소비된 committed를 지우고 새 결과를 삽입한다.

```
Transition: .replace(deleteCount: 이전 composing 수 + consumedCommittedCount,
                     insertText: result.committed + result.composing)
→ applyConsumedCommitted(count:)로 committedBuffer 동기화
→ committedBuffer += result.committed, composingBuffer = result.composing
```

마지막에 `lastInputText = result.input글자`를 저장한다(반복 입력용).

### 5-3. 삭제: `delete(using:)`

세 가지 분기가 있다.

**분기 1 — composing이 있을 때**: `deleteWithRestore종성` 호출 후
`.replace(deleteCount: 이전 composing 수 + consumed, insertText: 새 composing)`.
삭제 후 composing이 완전히 비면 `pullFromCommittedIfNeeded()`로 committed 끌어오기를 시도하고 그 Transition을 이어붙인다.

```
committedBuffer: "가나", composingBuffer: "ㄷ"
삭제 → composing "" → pullFromCommittedIfNeeded()
→ committed 마지막 "나".isHangeul → committedBuffer: "가", composingBuffer: "나"
→ 보호 범위가 아니면 processor.start한글조합()
→ isPulledFromProtected = (끌어온 글자가 보호 범위였는지)
→ 추가 Transition: .replace(deleteCount: 1, insertText: "나")
```

**분기 2 — composing이 비고 committed만 있을 때**: 마지막 글자가 한글이면 꺼내서
`deleteWithRestore종성(composing: 그 글자, ...)`로 자소 분해한다.

```
committedBuffer: "가나", composingBuffer: ""
삭제 → "나" 꺼냄 → processor 결과: composing "ㄴ"
→ Transition: .replace(deleteCount: 1 + consumed, insertText: "ㄴ")
→ committedBuffer: "가", composingBuffer: "ㄴ"
→ 결과 composing이 비면 reset한글조합(), 보호 범위가 아니면 start한글조합()
```

비한글(숫자, 기호)이면 단순 `.delete(count: 1)`이며 `reset한글조합()`한다.

**분기 3 — 둘 다 비었을 때**: `.delete(count: 1)` (커서 앞의 시스템 텍스트 삭제) + `reset한글조합()`.

모든 삭제는 `lastInputText = nil`로 반복 입력 상태를 끊는다.

### 5-4. 스페이스: `space(using:)`

```swift
let result = processor.inputSpace(composing: composingBuffer)
switch result {
case .commitCombination:   // 천지인: composing → committed 이동, protectedCommittedCount = committedBuffer.count
    return Transition(.none)
case .insertSpace:         // 두벌식/나랏글: 전체 버퍼 초기화 + reset한글조합
    return Transition(.insert(" "))
}
```

VC(`insertSpaceText`)는 `.insert(" ")`일 때 **Transition을 직접 적용하지 않고 `super.insertSpaceText()`를 호출**한다.
공백 삽입과 n-gram 기록(`recordUncommittedWords`)이 Base 공통 경로에서 일어나게 하기 위해서다.
`.none`(천지인 조합 확정)일 때는 `applyCompositionTransition`을 타므로 **공백도 들어가지 않고 n-gram 기록도 일어나지 않는다**.

### 5-5. 보호 상태: `protectedCommittedCount` / `isPulledFromProtected`

천지인의 스페이스는 공백이 아닌 "조합 확정"이므로, 확정된 글자에 이후 삭제로 종성이 다시 합쳐지면 안 된다.

- `.commitCombination` 시 `protectedCommittedCount = committedBuffer.count`로 설정한다.
- `isProtected = committedBuffer.count <= protectedCommittedCount`가 processor에 전달되어
  종성 복원(`tryMerge종성`)과 천지인 비표준 모음 끌어오기를 차단한다.
- `pullFromCommittedIfNeeded`/`finishRepeatDelete`에서 보호된 글자를 끌어오면 `start한글조합()`을 호출하지 않고
  `isPulledFromProtected = true`로 기억해 둔다. 이후 그 글자가 다시 committed로 돌아갈 때(`applyCompositionResult`)
  `protectedCommittedCount`를 복원하여 보호 상태를 유지한다.
- committed에서 글자를 제거하는 모든 경로는 `protectedCommittedCount = min(protectedCommittedCount, committedBuffer.count)`로 수축시킨다.

```
committedBuffer: "가" (보호됨, protectedCommittedCount=1), composingBuffer: ""
끌어오기 → committedBuffer: "", composingBuffer: "가", isPulledFromProtected = true
입력: "ㄴ" → 결과: committed "가", composing "ㄴ" (경로 A)
→ protectedCommittedCount 복원 → committedBuffer: "가" (다시 보호됨), composingBuffer: "ㄴ"
```

### 5-6. 반복 입력: `repeatInsert(using:)`

길게 누르기 반복 시 조합하지 않고 `lastInputText`를 그대로 삽입한다.
기존 composing은 committed로 넘기고 마지막 글자만 composing에 남겨, 반복 종료 후 다음 입력과 조합이 가능하다.

```
"ㄱ" 길게: ㄱ → ㄱㄱ → ㄱㄱㄱ (각각 committed로 이동, 마지막만 composing)
"ㅣ" 입력: composing "ㄱ" + "ㅣ" = "기" → 결과: "ㄱㄱ기"
```

`lastInputText`가 없으면(`hasRepeatableInput == false`) VC가 반복을 시작하지 않는다.

### 5-7. 반복 삭제: `repeatDelete(using:)` + `finishRepeatDelete(using:)`

반복 삭제는 자소 분해 없이 **글자 단위**로 지운다 (`.delete(count: 1)` + 버퍼 removeLast).
반복이 끝나면(`repeatTextInteractionDidPerform`) `finishRepeatDelete`가 committed 마지막 한글을 composing으로 끌어와
조합을 재개한다 (`.replace(deleteCount: 1, insertText: 그 글자)`, 보호 범위면 `start한글조합()` 생략).

### 5-8. 외부 변경 리셋: `clearAllBuffers()`

버퍼, 보호 상태, 삭제 팬 임시 상태, `lastInputText`를 전부 초기화한다.
Adapter의 `clearForExternalTextChange()`가 이것과 `processor.reset한글조합()`을 함께 호출하며, 호출 시점은 §8 참조.

## 6. 삭제 팬 제스처와 touchDown 스냅샷

삭제 버튼을 좌우로 드래그하면 글자 단위 삭제/복구가 일어난다. State가 관련 상태를 함께 관리한다.

### 팬 삭제: `deleteButtonPanDelete(using:)`

- composing이 있으면 composing 마지막 글자, 없으면 committed 마지막 글자를 제거하고
  `HangeulDeletePanResult(character:shouldRestore:transition:)`을 반환한다. Transition은 항상 `.delete(count: 1)`.
- `shouldRestore == true`인 글자는 `temporaryDeletedCharacters`에 쌓여 오른쪽 팬으로 복구할 수 있다.
- 버퍼가 모두 비어 있으면 `nil`을 반환하고, VC는 proxy의 `documentContextBeforeInput` 마지막 글자를 직접 지운다.

### 팬 복구: `deleteButtonPanRestore(_:using:)`

복구 글자가 한글이면 composing으로 넣고 `start한글조합()`, 아니면 committed에 붙이고 `reset한글조합()`.
기존 composing이 있었다면 committed로 넘긴다. Transition은 `.insert(글자)`.

### touchDown 스냅샷 보정

단일 삭제(touchDown)는 자소를 분해한다(예: `"가"` → `"ㄱ"`, 또는 종성 복원으로 committed까지 변형).
그 직후 팬 삭제로 넘어가면 "화면에 보이는 글자"와 "복구해야 할 글자"가 달라진다. 이를 위해:

- `beginDeleteButtonTouchDown()`이 삭제 전 composing/committed 스냅샷을 찍는다.
- `endDeleteButtonTouchDown()`이 두 값을 계산한다:
  - `shouldSkipNextDeletePanRestore`: 삭제 전에도 composing이 있었고 삭제 후에도 남아 있으면(자소 분해가 일어난 경우) `true`.
    다음 팬 삭제 1회는 지운 글자를 복구 버퍼에 그대로 넣지 않는다.
  - `nextDeletePanRestoreReplacement`: 종성 복원으로 committed 글자가 소비된 경우 등,
    다음 팬 삭제 시 복구 버퍼에 대신 넣을 원래 글자.

```
예: committedBuffer "가", composingBuffer "나"
touchDown 삭제 → 종성 복원 → composingBuffer "간" (committed "가" 소비)
이어서 팬 삭제 → 화면에서 "간"이 지워지지만, 복구 버퍼에는 대체 글자 "가"가 들어감
→ 오른쪽 팬 복구 시 사용자가 실제로 입력했던 "가"가 돌아옴
```

팬 종료(`finishDeletePan`) 시 임시 상태를 모두 정리한다.
Base 쪽 삭제 확정 파이프라인과의 연결은 [삭제와 실행취소 로직](삭제와%20실행취소%20로직.md) 참조.

## 7. 세 입력기의 차이점

| | 두벌식 | 나랏글 | 천지인 |
|---|---|---|---|
| `is한글조합OnGoing` | 항상 `false` | 항상 `false` | 동적 관리 |
| `inputSpace` | 항상 `.insertSpace` | 항상 `.insertSpace` | 조합 중이면 `.commitCombination` |
| `start한글조합`/`reset한글조합` | 빈 구현 | 빈 구현 | 플래그 토글 |
| 고유 입력 기능 | 없음 (오토마타 위임) | 획추가/쌍자음/모음 토글/ㅣ결합/이중모음 | 자음 순환/천지인 모음 조합 |
| 고유 삭제 기능 | composing 내부 종성 복원 | ㅣ결합·이중모음 분해 | 비표준 모음 처리 + committed 끌어오기 |

스페이스 버튼 이미지는 `isCompositionOngoing`(= `processor.is한글조합OnGoing`)에 따라
`"arrow.right"`(조합 확정) ↔ `"space"`(공백)로 바뀐다. 사실상 천지인에서만 화살표가 표시된다.

### 7-1. 두벌식 (DubeolsikProcessor)

가장 단순한 입력기. 입력은 전부 `automata.add글자()`에 위임한다.

`delete()`는 오토마타 삭제 후, 남은 텍스트가 2글자 이상이고 마지막이 종성 가능 자음이면 내부 종성 복원을 시도한다.

```
composing: "갈가" → automata.delete글자() → "갈ㄱ"
→ "ㄱ"이 종성Table에 있음 → automata.add글자("ㄱ", "갈") → "갉" → 결과: composing "갉"
```

입력 흐름 예시 ("한글"):

```
"ㅎ" → ("", "ㅎ")    "ㅏ" → ("", "하")    "ㄴ" → ("", "한")
"ㄱ" → ("한", "ㄱ")  ← "한" 확정          "ㅡ" → ("", "그")    "ㄹ" → ("", "글")
```

### 7-2. 나랏글 (NaratgeulProcessor)

12키 기반. 기본 입력은 오토마타에 위임하되 특수 키 처리 우선순위가 있다.

```
1. "획" / "쌍"   → 획추가/쌍자음 변환
2. "ㅣ"          → 모음 결합 시도 (ㅏ→ㅐ, ㅝ→ㅞ 등. 실패 시 아래로)
3. "ㅏ"/"ㅓ"     → 이중모음 시도 (무+ㅓ→뭐, 보+ㅏ→봐. 실패 시 아래로)
4. ㅏ/ㅓ/ㅗ/ㅜ   → 모음 토글 시도 (ㅏ↔ㅓ, ㅗ↔ㅜ. 실패 시 아래로)
5. 일반 입력     → automata.add글자()
```

**획추가**: composing 마지막 글자에서 종성 → 중성 → 낱자 순으로 `획추가Table` 변환을 시도한다.

```
composing: "간", 입력: "획" → 종성 "ㄴ" → "ㄷ" → composing: "갇"
composing: "갉", 입력: "획" → 겹받침 분해 ("ㄹ","ㄱ") → 뒷받침 "ㄱ"→"ㅋ" → "갈" + add글자("ㅋ") 
```

**쌍자음**: 같은 구조로 `쌍자음Table` 사용. 변환 결과가 종성으로 쓸 수 없는 자음이면
(예: `"옴"` + 쌍 → `ㅁ`→`ㅃ`) 앞 글자를 확정하고 쌍자음을 새 composing으로 시작한다.

**모음 토글**: `composing: "가"` + `"ㅏ"` → `"거"` → 다시 `"ㅏ"` → `"가"`.

**삭제**는 역순 특수 처리: ① ㅣ결합 분해(ㅐ→ㅏ) ② 이중모음 분해(ㅝ→ㅜ) ③ `automata.delete글자()`.

획추가/결합류의 `input글자`에는 반복 입력용 대표 문자가 들어간다(예: ㅙ→ㅐ, ㅘ→ㅏ로 치환).

### 7-3. 천지인 (CheonjiinProcessor)

가장 복잡한 입력기. 세 가지 고유 메커니즘이 있다.

**① `is한글조합OnGoing` 상태 관리**

```
false 상태에서 한글 입력 → 기존 composing 전체 확정 + 새 글자로 조합 시작 + true 전환 (applyCompositionResult 경로 A)
true 상태에서 한글 입력  → 기존 composing과 조합 계속
스페이스                → 조합 중이면 commitCombination + false 전환, 아니면 insertSpace
비한글 입력             → commitAll + false 전환
```

자음 순환 중 "이어서 조합할 글자"인지 "새 글자"인지 구분하기 위해 필요하다.
State 쪽의 `start한글조합()`/`reset한글조합()` 호출(끌어오기, 팬 복구, 외부 리셋)과 함께 움직인다.

**② 자음 순환** (`자음순환Table`)

```
ㄱ → ㅋ → ㄲ → ㄱ   /   ㄴ → ㄹ   /   ㄷ → ㅌ → ㄸ   /   ㅂ → ㅍ → ㅃ
ㅅ → ㅎ → ㅆ        /   ㅈ → ㅊ → ㅉ   /   ㅇ → ㅁ
```

낱자·종성·겹받침의 뒷받침까지 순환 대상이다.

```
composing: "각", 입력: "ㄱ" → 종성 "ㄱ" 순환 → "갘"
composing: "갃", 입력: "ㅅ" → 겹받침 "ㄳ" 분해 → 뒷받침 "ㅅ" 순환 → "각" + add글자("ㅎ")
```

**③ 천지인 모음 조합** (`모음조합Table`, 천ㆍ/지ㅡ/인ㅣ)

```
"ㅣ"+"ㆍ"="ㅏ", "ㅏ"+"ㆍ"="ㅑ", "ㆍ"+"ㆍ"="ᆢ", "ᆢ"+"ㅣ"="ㅕ", "ㅡ"+"ㆍ"="ㅜ", "ㆍ"+"ㅡ"="ㅗ", ...
```

비표준 모음(ㆍ, ᆢ)은 중간 상태로만 존재하며 composing에 직접 붙는다.
표준 모음이 완성되면 `automata.add글자()`에 위임되어 연음까지 처리된다.

```
composing: "가", 입력: "ㆍ" → decompose("가") → 초성 "ㄱ" + 중성 "ㅏ" → "ㅏ"+"ㆍ"="ㅑ" → add글자("ㅑ", "ㄱ") → "갸"
composing: "닭" 뒤 "ㆍ"+"ㅣ"="ㅓ" → add글자("ㅓ", ...) → "달"+"거" 연음
```

**천지인 delete() 고유 로직**

1. composing에 비표준 모음이 포함되어 있으면 오토마타에 위임하지 않고 마지막 글자만 단순 제거한다.
   ```
   composing: "간ㆍ" → "간"
   ```
2. 오토마타 삭제 후 남은 마지막 글자가 종성 가능 자음이면 composing 내부 종성 복원을 시도한다(두벌식과 동일 패턴).
3. `tryRestore비표준모음ToCommitted`: 삭제 후 남은 composing이 0글자 또는 종성 가능 자음 1개이고,
   committedTail 끝이 비표준 모음이면 committedTail 전체를 composing으로 끌어올린다
   (`consumedCommittedCount = committedTail.count`, 최대 2). 보호 상태면 하지 않는다.
   ```
   committedTail: "간ㆍ", 삭제 후 remaining: "ㄷ"
   → composing: "간ㆍㄷ", consumedCommittedCount: 2
   → 이후 모음 입력(ㆍ+ㅣ=ㅓ)으로 "간" → "가너" 연음 가능
   ```

표준 한글과의 종성 합치기는 프로토콜 기본 구현(`deleteWithRestore종성`)에서 처리한다.

## 8. 오토마타 (HangeulAutomata)

프로세서들이 공유하는 표준 한글 자소 합치기/분해 엔진. `HangeulAutomataProtocol`로 추상화되어 있다.

### add글자 — 글자 합치기

```
입력이 모음인 경우:
  1-1. 종성 있는 완성형 + 모음 → 연음 ("각"+"ㅏ" → "가" 확정 + "가")
       겹받침이면 분리 후 연음 ("닭"+"ㅏ" → "달" 확정 + "가")
  1-2. 종성 없는 완성형 + 모음 → 겹모음 시도 ("고"+"ㅏ" → "과")
  낱자 자음 + 모음 → 결합 ("ㄱ"+"ㅏ" → "가")
  낱자 모음 + 모음 → 겹모음 시도 ("ㅜ"+"ㅓ" → "ㅝ")

입력이 자음인 경우:
  2-1. 종성 없는 완성형 + 자음 → 종성 추가 ("가"+"ㄱ" → "각")
  2-2. 종성 있는 완성형 + 자음 → 겹받침 시도 ("각"+"ㅅ" → "갃")

모든 조건 실패 → composing 전체 확정 + 새 글자 시작
```

### delete글자 — 글자 분해

```
완성형 한글:
  종성 있음 → 겹받침이면 앞부분만 ("닭" → "달"), 홑받침이면 제거 ("각" → "가")
  종성 없음 → 겹모음이면 앞부분만 ("과" → "고"), 단모음이면 초성만 ("가" → "ㄱ")
낱자:
  겹모음이면 분해 ("ㅘ" → "ㅗ"), 아니면 그냥 삭제
```

### combine / decompose — 유니코드 연산

```
한글 유니코드 = 0xAC00 + (초성Index × 21 × 28) + (중성Index × 28) + 종성Index
```

`decompose겹받침(종성:)`은 겹자음조합Table 역방향 조회다.

## 9. 외부 텍스트 변경과 상태 리셋

버퍼와 실제 텍스트가 어긋날 수 있는 모든 시점에 Adapter의 `clearForExternalTextChange()`
(= `state.clearAllBuffers()` + `processor.reset한글조합()`)를 호출한다.

| 시점 | 호출 위치 |
|---|---|
| 텍스트 필드 전환, 커서 이동, 필드 탭 | `textWillChange(_:)` |
| undo/redo 적용 직후 | `undoRedoEditDidApply()` |
| 자동완성 후보/수식 결과 적용 직후 | `suggestionDidApply()` |
| 기호 키보드에서의 입력, 리턴 입력 | `insertPrimaryKeyText`(symbol 분기), `insertReturnText` |
| 스페이스(공백 삽입 경로) | `space()` 내부에서 State가 자체 초기화 |
| 한영 전환 | `finishForLanguageChange()` |

`textWillChange`/`suggestionDidApply` 후에는 스페이스 버튼 이미지와 Shift 상태도 함께 갱신한다.

### undo/redo와의 연결

`shouldDeferUndoRedoCommit`은 `!composingBuffer.isEmpty`를 반환한다.
조합이 진행 중인 동안 undo 편집 단위 확정을 미루고, 조합이 끝나는 입력에서
`commitDeferredUndoRedoGroupIfNeeded()`가 호출된다. 상세는 [삭제와 실행취소 로직](삭제와%20실행취소%20로직.md) 참조.

## 10. 자동완성과의 접점

- 모든 proxy 편집이 Base 래핑 메서드를 거치므로 `inputBuffer`는 조합 완료 문자열로 유지된다.
- 스페이스: Base의 `.spaceButton` 분기에서 ① 수식 후보 적용 시도 → ② 텍스트 대치 시도 → ③ `insertSpaceText()` 순서.
  한글 VC의 `insertSpaceText()`는 `.insert(" ")`일 때만 `super`(공백 삽입 + n-gram 기록)를 호출하므로,
  **천지인 조합 확정 스페이스에서는 텍스트 대치 결과만 반영되고 공백·n-gram 기록은 없다.**
- 삭제: Base가 먼저 텍스트 대치 복구를 시도하고, 실패하면 한글 `deleteBackward()`(자소 분해)로 진행한다.
- 후보/수식 적용 후 `suggestionDidApply()`가 조합을 리셋하므로, 후보 적용 직후 입력은 항상 새 조합으로 시작한다.

상세는 [자동완성 로직 §9](자동완성%20로직.md) 참조.
