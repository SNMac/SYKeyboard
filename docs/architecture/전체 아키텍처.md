## 2. 런타임 구조

세 개의 keyboard extension이 하나의 Base 컨트롤러를 공유한다.

```
UIInputViewController
└── BaseKeyboardViewController                     (SYKeyboardCore, 입력 흐름의 중심)
    ├── HangeulKeyboardCoreViewController          (HangeulKeyboardCore)
    │   └── HangeulKeyboardViewController          (HangeulKeyboard extension 진입점)
    ├── EnglishKeyboardCoreViewController          (EnglishKeyboardCore)
    │   └── EnglishKeyboardViewController          (EnglishKeyboard extension 진입점)
    └── HangeulEnglishKeyboardViewController       (Core VC 없이 Base를 직접 상속, Adapter 2개 보유)
```

`BaseKeyboardViewController`(`Modules/SYKeyboardCore/Presentation/ViewController/Bases/BaseKeyboardViewController.swift`)의 책임:

- **텍스트 프록시 래핑**: `insertText(_:)` / `insertTypedText(_:)` / `deleteText()` / `replaceText(deleteCount:insert:)`.
  `textDocumentProxy`를 직접 조작하지 않고 이 메서드를 거쳐 `inputBuffer`·n-gram 문장 버퍼·undo 기록이 항상 함께 동기화된다.
- **`inputBuffer` 관리**: 현재 키보드 세션에서 직접 입력한 텍스트만 추적. 커서 이동·키보드 열림/닫힘·`textWillChange`에서 초기화.
  한영 통합 키보드도 언어 경계로 나누지 않고 같은 `inputBuffer`를 그대로 자동완성에 전달한다(단어 완성·대치/복구·
  수식 인식·NGram 기록·조회·삭제 뒤 문장 버퍼 동기화·NGram 후보 앞 공백 삽입 여부 모두). 한/A 전환은 자판만
  바꾸고 후보 바·대치 이력·NGram 문장 버퍼는 그대로 유지한다.
- **자동완성 연동**: `SuggestionController`(프로토콜 `SuggestionService`) 보유, `SuggestionBarDelegate`/`SuggestionControllerDelegate` 구현.
  후보를 길게 누르면(`suggestionBar(_:shouldBeginRemovalAt:)`) `DeleteConfirmOverlayView`로 삭제 확인을 띄우고,
  확인되면 학습된 단어를 지운다. → [자동완성 로직](자동완성%20로직.md) 6-1
- **undo/redo**: `KeyboardUndoRedoSession` 보유, SuggestionBar 우측 undo/redo 버튼 처리.
- **삭제 파이프라인**: `DeleteMutationLifecycle` + `DeleteInteractionCoordinator`로 삭제 요청을 실제 텍스트 변경 확인 후 확정.
- **제스처**: `TextInteractionGestureController`(커서 드래그, 삭제 드래그, 길게 누르기), `SwitchGestureController`(키보드 전환, 한 손 모드).
- **높이/한 손 모드**: `KeyboardHeightPolicy`, `OneHandedMode`, chevron 버튼.
- **호스트 동기화**: `textWillChange`/`textDidChange`, keyboardType별 레이아웃 전환, 리턴 버튼 상태, Smart Punctuation.

하위 VC는 `open` 프로퍼티/메서드(`primaryKeyboardView`, `primaryKeyboardViews`, `updateKeyboardType()`,
`shouldDeferUndoRedoCommit`, `smartQuoteRule`, `insertPrimaryKeyText(from:)`, `inputTraitsDidChange()` 등)를 오버라이드해 언어별 차이만 주입한다.
언어 공통 동작은 하위 VC가 아니라 Base 또는 Policy에 있다.

### InputAdapter 경계

언어별 입력 로직은 Adapter를 통해서만 들어온다. Adapter가 VC와 Domain 사이의 유일한 경계다.

```
HangeulKeyboardCoreViewController ──▶ HangeulKeyboardInputAdapter ──▶ HangeulCompositionState ──▶ Processor/Automata
EnglishKeyboardCoreViewController ──▶ EnglishKeyboardInputAdapter  (Shift/CapsLock/자동 대문자 상태)
HangeulEnglishKeyboardViewController ──▶ 두 Adapter를 함께 보유, HangeulEnglishKeyboardModeCoordinator가 언어 결정
```

- 한글 Adapter는 조합 계산 결과를 `HangeulCompositionTransition`(proxy 편집 명령 목록)으로 반환하고,
  VC는 이를 Base의 래핑 메서드로 실행만 한다. → [한글 입력 로직](한글%20입력%20로직.md)
- 영문 Adapter는 텍스트를 직접 만들지 않는다. VC가 `insertTypedText(_:)`로 입력하고,
  Adapter는 Shift/CapsLock/자동 대문자와 레이아웃 모드 상태만 관리한다.

## 3. 뷰 계층

```
KeyboardView (UIInputView, SYKeyboardAssets 번들의 KeyboardView.xib에서 로드)
└── keyboardFrameVStackView
    ├── suggestionBarView (SuggestionBarView: 클립보드 버튼 + 후보 가로 스크롤 영역(3칸 표시, 후보 최대 10개) + undo/redo 버튼)
    └── keyboardHStackView
        ├── leftChevronButton   (한 손 모드 오른손 배치 시 해제 버튼)
        ├── keyboardLayoutView  (primary/symbol/numeric/tenkey 키보드와 clipboardHistoryPanelView가 전부 겹쳐 있고 isHidden으로 전환)
        └── rightChevronButton  (한 손 모드 왼손 배치 시 해제 버튼)
```

- `KeyboardView.loadFromNib(primaryKeyboardViews:)`로 초기화하고 `loadView()`에서 `self.view`에 할당한다.
  (코드 베이스 레이아웃에서 `UIInputView`가 해제되지 않는 iOS 버그 대응 — README 트러블 슈팅 참조)
- 높이 제약(키보드 높이, SuggestionBar 높이)은 999 priority를 사용한다.
  회전 도중이나 시스템 개입 시 Auto Layout이 양보할 수 있게 하기 위함이다.
- 한 손 모드는 `keyboardLayoutView`의 최소 너비 제약(`oneHandedKeyboardWidth`)으로 구현된다.
  이 제약은 required다(999면 `keyboardHStackView` 내부 제약에 밀려 무시된다). 회전 중 충돌은
  `updateKeyboardLayoutWidthConstraint()`가 `KeyboardPresentationStatePolicy.oneHandedKeyboardMinimumWidth`로
  상수를 가용 폭 안으로 낮춰 막는다.

```

├── PrimaryButton   → PrimaryKeyButton, SpaceButton
```

## 4. 버튼 이벤트 타이밍

버튼 하나의 터치가 어떤 순서로 처리되는지가 키보드 반응성의 핵심이다.

| 이벤트 | 동작 |
|---|---|
| `touchDown` (모든 버튼) | `ButtonStateController.setFeedbackActionToButtons`: 피드백 재생 + `currentPressedButton` 갱신. 이전에 눌린 버튼이 남아 있으면 그 버튼에 `touchUpInside`를 강제 발송해 입력을 먼저 확정(빠른 연속 입력 대응). `ShiftButton`만 `currentPressedButton`을 갱신하지 않고 `isShiftButtonPressed`를 켠다 |
| `touchUpInside` (일반 키/스페이스/리턴) | `performTextInteraction(for:)` 실행. `currentPressedButton == 눌린 버튼`일 때만 입력 수행 (`isProgrammaticCall`이면 무조건 수행) |
| `touchDown` (삭제 버튼) | 삭제는 누르는 즉시 수행. 떼는 시점에는 `DeleteMutationLifecycle.finishTouchDown`으로 삭제 확정만 처리 |
| `touchDownRepeat` (스페이스) | '.' 단축키: `KeyboardPeriodShortcutPolicy.shouldReplaceTrailingSpaceWithPeriod` 판정 후 `replaceText(deleteCount: 1, insert: ".")` |
| 팬 제스처 (일반 키) | `cursorActiveDistance` 이상 이동 시 커서 드래그 모드 활성화. `CursorDragAccelerationPolicy`가 속도/가속도로 step(최대 4) 계산, `adjustTextPosition` 호출. 드래그 중 `inputBuffer` 초기화, 후보 갱신 중단(`isPrimaryCursorDragging`) |
| 팬 제스처 (삭제 버튼) | 왼쪽: 글자 단위 삭제 + 임시 버퍼(`tempDeletedCharacters`) 저장, 오른쪽: 복구. → [삭제와 실행취소 로직](삭제와%20실행취소%20로직.md) |
| 길게 누르기 | `LongPressAction` 설정에 따라 반복 입력(`repeatInput`, 기본값), 보조 키 입력(`numberInput`, `secondaryKey` 삽입), 사용 안 함(`disabled`, 삭제 버튼 외에는 길게 누르기 제스처를 붙이지 않음). `secondaryKey`는 평소에는 숫자이고, 숫자 행이 켜진 두벌식·쿼티에서는 같은 자리의 shift 짝 문자다(`KeyboardTextInteractionPolicy.shiftPairSecondaryKeyList`). 비shift 층은 shift 문자(대문자·쌍자음)를, shift 층은 반대로 비shift 문자를 보조 키로 쓰고, 두 층의 문자가 같으면(두벌식 ㅁ, ㅛ 등) 보조 키를 두지 않는다. 삭제 버튼은 설정과 무관하게 항상 반복 삭제. 반복 입력은 인식 즉시 `performInitialRepeatTextInteraction`이 첫 글자를 입력하고 이후 반복 타이머가 이어서 입력한다. 인식되면 버튼 터치가 취소되어 `touchUpInside`가 오지 않으므로, 기호 키보드의 기호 입력 기록과 작은따옴표 복귀는 길게 누르기 입력 경로에서 따로 처리한다 |
| 반복 타이머 | `Timer.publish(every: max(0.01, 0.10 - repeatRate))`. 텍스트 필드가 바뀌거나 window에서 분리되면 자동 중단 |
| `SwitchButton` 팬 | `SwitchGestureController`: 키보드 선택 오버레이(숫자 키패드 활성 시), 한 손 모드 선택(팬+길게 누르기) |

입력 전후 훅: `textInteractionWillPerform(button:)` → 입력 수행 → `textInteractionDidPerform(button:)`.
`didPerform`에서 반복 입력 중이 아니면 리턴 버튼 상태와 자동완성 후보를 갱신한다.
반복 입력은 `repeatTextInteractionWillPerform`/`repeatTextInteractionDidPerform`이 감싼다.
`repeatTextInteractionWillPerform`은 삭제 버튼을 제외하고 `performInitialRepeatTextInteraction`으로 첫 입력을 수행하며,
한글 VC와 한영 VC(한글 모드)는 이 메서드를 오버라이드해 `hasRepeatableInput || SpaceButton`일 때만 피드백을 재생한다.

### Smart Punctuation

사용자가 키로 입력한 텍스트만 `insertTypedText(_:)` → `KeyboardSmartInputPolicy.transformTypedText`를 거친다.

- **Smart Quotes**: `smartQuoteRule`에 따라 분기. 한글 계열(`koreanSystem`)은 따옴표 토글 상태(`KeyboardSmartQuoteState`) 기반,
  영문 계열(`englishSystem`)은 커서 앞 문자 기반으로 여닫이를 결정한다.
  `treatsDefaultSmartQuotesAsEnabled`는 `smartQuotesType == .default`일 때의 해석을 결정한다(한글 VC `true`, 영문 VC `false`).
- **Smart Dashes**: `--` → `—`, `...` → `…`.
- **Smart Insert/Delete**: 자동완성 후보·텍스트 대치 삽입 시 `smartInsertDeleteLeadingSpacePrefix`로 필요하면 앞 공백을 붙인다.

## 5. Policy 카탈로그

분기 로직과 임계값은 VC의 if문이 아니라 UI 의존이 없는 순수 타입으로
`Modules/SYKeyboardCore/Presentation/Utils/Policies/`에 분리되어 있고, 각각 대응하는 테스트가 있다.

| Policy | 역할 | 테스트 |
|---|---|---|
| `KeyboardHeightPolicy` | 세로/가로별 키보드·스택 높이 계산, 숫자 행 높이(`numberRowHeight`, 세로는 높이 설정 비례·가로는 고정), 방향 판정(iOS 27+에서는 VC가 orientation 대신 size class 판정을 선택) | `KeyboardHeightPolicyTests` |
| `KeyboardGesturePolicy` | 제스처 부착/동작 조건, 커서 드래그 햅틱, edge 터치 시스템 제스처 설정 | `KeyboardGesturePolicyTests` |
| `KeyboardSmartInputPolicy` | Smart Quotes/Dashes/Insert-Delete 변환 | `KeyboardSmartInputPolicyTests` |
| `KeyboardPeriodShortcutPolicy` | '.' 단축키 수행/방지 상태 전이 | `KeyboardPeriodShortcutPolicyTests` |
| `CursorDragAccelerationPolicy` | 커서 드래그 step 가속(속도 900/1600, 가속 900 임계값, 최대 4 step) | `CursorDragAccelerationPolicyTests` |
| `KeyboardSuggestionSelectionPolicy` | 후보 갱신 대상 결정, 수식 탐지 텍스트 선택, 후보 삭제 길게 누르기 시간(`removalLongPressDuration` 0.5초, 사용자 설정과 별개) | `KeyboardSuggestionSelectionPolicyTests` |
| `KeyboardPresentationStatePolicy` | SuggestionBar 숨김, 리턴 버튼 활성, undo/redo·수식 표시 조건, 한 손 모드 최소 너비 계산 | `KeyboardPresentationStatePolicyTests`, `OneHandedKeyboardWidthPolicyTests` |
| `KeyboardTextInteractionPolicy` | 삭제 확정 파이프라인 타입들, 반복 타이머 간격, 임시 삭제 문자 계산, 숫자 행용 shift 짝 보조 키 목록 | `KeyboardTextInteractionPolicyTests` |
| `KeyboardSymbolInputPolicy` | 기호 키보드에서 주 키보드 자동 복귀 조건 (길게 누르기 입력 포함) | `KeyboardSymbolInputPolicyTests` |
| `KeyboardLanguageModePolicy` | 한영 통합 시작 언어/자동 전환 판정 | `KeyboardLanguageModePolicyTests` |
| `KeyboardSelectDirectionPolicy` | 키보드 선택 오버레이 방향 판정 | `KeyboardSelectDirectionPolicyTests` |
| `KeyboardColumnWidthPolicy` | 4x4 계열 글자 열 너비 배율 | `KeyboardColumnWidthPolicyTests` |
| `SuggestionHighlightPolicy` | 후보/undo·redo 버튼 하이라이트 우선순위(터치 > preview) | `SuggestionHighlightPolicyTests` |
| `SuggestionDividerPolicy` | 후보 영역 divider 개수(후보가 3개보다 적어도 3칸 격자). `SuggestionHighlightPolicy.swift` 안에 있다 | `SuggestionDividerPolicyTests` |
| `PredictiveTextCompletionMatchPolicy` | 입력 중 NGram 단어 완성의 접두어 판정(대소문자 무시, 마지막 글자 자모 단위·겹받침 분해, 천지인 조합 중 모음 제외, 입력 단어 제외)과 표시 표기(`displayText(for:)`) | `PredictiveTextCompletionMatchPolicyTests`, `HangeulCompletionMatchScenarioTests` |
| `ClipboardHistoryPolicy` | 클립보드 기록 저장 규칙(중복 제거, 미고정 20개·고정 20개, 10,000자 제한, 고정 순서) | `ClipboardHistoryPolicyTests` |
| `ClipboardImagePolicy` | 클립보드 이미지 저장 한도(바이트·픽셀 수), 허용 타입, 썸네일·미리보기 크기 | `ClipboardImagePolicyTests` |

Policy는 아니지만 같은 성격의 순수 타입: `HangeulEnglishKeyboardModeCoordinator`(Coordinators/),
`KeyboardUndoRedoManager`/`KeyboardTextContextNavigator`(Utils/), `DeleteMutationLifecycle`/`DeleteInteractionCoordinator`(KeyboardTextInteractionPolicy.swift 내),
`ClipboardHistoryPasteboardSynchronizer`(Storage/, 시스템 pasteboard → 기록 반영, 앱·extension 공용),
`KeyboardDiagnostics`(Utils/, 입력 텍스트를 제외한 조작 흐름을 크래시 리포트에 남기고 Debug 빌드에서는 `installConstraintConflictLogging()`으로 Auto Layout 제약 충돌도 기록).

## 7. 수명주기와 호스트 동기화

| 시점 | 동작 |
|---|---|
| `loadView` | XIB에서 `KeyboardView` 로드 |
| `viewDidLoad` | `KeyboardDiagnostics.installConstraintConflictLogging()`, `inputBuffer` 초기화, UI/delegate/action 설정, 클립보드 동기화용 알림 관찰(`NSExtensionHostDidBecomeActive`, `UIPasteboard.changedNotification`, 이미지 기록 완료), 자동완성 **설정만** 전달(엔진 생성 지연). 텍스트 대치가 켜져 있으면 lexicon 로드만 먼저 시작 |
| `viewWillAppear` | 키보드 높이 제약 설정(`KeyboardHeightPolicy`), 클립보드 기록 동기화(`synchronizeClipboardHistoryIfNeeded`), 햅틱 준비 |
| `viewDidAppear` | `startDeferredSuggestionPreparationIfNeeded()`: 예측 엔진 생성 + lexicon 로드 + 초기 후보 갱신(첫 표시 이후 1회) |
| `viewWillLayoutSubviews` | `needsInputModeSwitchKey` 변경 시에만 지구본 버튼 재설정 |
| `textWillChange` | 호스트 text input 식별자 비교 → 바뀌었으면 `textInputDidChange` 훅 실행(아래 주의 참조). traits 동기화, undo/redo 준비, `inputBuffer` 초기화, keyboardType/리턴 버튼/SuggestionBar 갱신, 클립보드 패널 닫기(`closeClipboardPanelIfNeeded`)와 기록 동기화 |
| `textDidChange` | traits 동기화, 커서 드래그 햅틱 판정, **삭제 확정 파이프라인 완료 처리**, undo 이력 무효화 판정, keyboardType 갱신, `keyboardType`/`textContentType`이 바뀌었으면 `inputTraitsDidChange` 훅 실행, 리턴 버튼/SuggestionBar 갱신, 후보 갱신(커서 드래그 중 제외) |
| `viewWillDisappear` | 반복 입력 중단, 클립보드 패널 닫기, 후보 삭제 확인 오버레이 닫기, undo 이력 제거, `inputBuffer` 초기화, n-gram 디스크 저장 |
| `didReceiveMemoryWarning` | 비활성 언어의 예측 엔진 캐시 해제, 클립보드 패널 썸네일 캐시 해제(`purgeThumbnailCache`) |

각 단계의 signpost 구간과 지연 생성·메모리 결정의 이유는 [성능 고려 사항 §2-1 · §2-7](성능%20고려%20사항.md)에 있다.

호스트 콜백의 실제 동작 특성:

- `selectionWillChange(_:)`/`selectionDidChange(_:)`는 현재 확인된 환경에서 호출이 관찰되지 않았다.
  그래서 코드는 이 콜백에 의존하지 않고 로그만 남긴다.
- 텍스트 필드 전환, 사용자의 필드 탭, 커서 이동 시에는 `textWillChange`/`textDidChange`가 호출된다.
  외부 텍스트 컨텍스트 변경에 따른 상태 동기화는 전부 이 경로에 모여 있다.
- 두 콜백의 `textInput` 인자는 키보드 extension에서 항상 nil로 들어온다. 실기기(iPhone 15 Pro Max, iOS 27.0)에서
  메모·Safari·메시지·메일의 입력, 커서 이동, 삭제, 필드·앱 전환, 프로세스 재생성까지 모든 호출이 nil이었다.
  nil이면 식별자도 nil이라 `textInputDidChange` 훅과 식별자 기반 판정은 extension에서 동작하지 않는다.
  필드가 바뀐 것은 `textDidChange`에서 `keyboardType`/`textContentType` 변화로 대신 감지해
  `inputTraitsDidChange()` 훅을 부른다. trait이 같은 필드 사이의 전환은 이 신호로 구분되지 않는다.

### 키보드 높이

```
세로: keyboardView 높이 = keyboardHeight 설정값 + (SuggestionBar 표시 시 suggestionBarHeightWithTopSpacing) + 숫자 행 높이
가로: keyboardView 높이 = landscapeKeyboardHeight + 숫자 행 높이, 내부 스택이 SuggestionBar만큼 줄어듦
```

숫자 행 높이(`KeyboardHeightPolicy.numberRowHeight`)는 숫자 행이 켜져 있을 때만 0이 아니다. 두벌식·쿼티·나랏글·천지인
모두 숫자 행을 쓰고, 각 베이스 뷰와 기호 자판은 `KeyboardNumberRow`로 숫자 행을 만든다. `setKeyboardHeight()`는 설정값(`showsNumberRow`)이 아니라 실제로 만들어진 뷰의 `showsNumberRow`로 판단해,
extension이 살아 있는 동안 설정이 바뀌어도 뷰와 프레임 높이가 어긋나지 않게 한다.
같은 높이를 주 자판과 기호 자판에 `updateNumberRowHeight`로 전달한다.
세로 숫자 행은 설정 최소값(190)일 때의 글자 행 높이 46.5pt에서 시작해 글자 행 증가폭의 절반
(`portraitNumberRowGrowthRatio`)만큼 커진다(`46.5 + (글자 행 − 46.5) × 0.5`, 설정 240에서 52.75pt,
290에서 59pt). 숫자 행이 항상 글자 행보다 낮은 보조 행으로 보이게 하려는 것이다. 가로는 높이 설정이
적용되지 않으므로 35pt 고정이다.
앱 설정 미리보기는 `setKeyboardHeight()`를 거치지 않으므로 `updateNumberRowHeightForPreview(to:)`로 같은 값을 전달한다.

SuggestionBar 표시 여부가 바뀌면(`updateSuggestionBarHidden`) 높이를 재계산한다.
숨김 조건: 텐키 키보드 ∨ (후보 영역 사용 불가 ∧ undo/redo 꺼짐 ∧ 클립보드 기록 꺼짐)
(`KeyboardPresentationStatePolicy.shouldHideSuggestionBar`).
후보 영역·undo/redo·클립보드 중 하나라도 쓸 수 있으면 바를 보여주고, 쓸 수 없는 것만 비운다.
후보 영역 사용 가능 = 자동완성 켜짐 ∧ `autocorrectionType != .no`.

## 8. 검증

기본 검증 명령 (기준 시뮬레이터: `iPhone 13 mini / iOS 18.6`):

```sh
xcodebuild -list -project SYKeyboard.xcodeproj

xcodebuild test \
  -project SYKeyboard.xcodeproj \
  -scheme SYKeyboard \
  -destination 'platform=iOS Simulator,name=iPhone 13 mini,OS=18.6'

xcodebuild build \
  -project SYKeyboard.xcodeproj \
  -scheme HangeulEnglishKeyboard \
  -destination 'platform=iOS Simulator,name=iPhone 13 mini,OS=18.6'
```

공유 scheme은 `SYKeyboard`, `HangeulKeyboard`, `EnglishKeyboard`, `HangeulEnglishKeyboard` 4개이며,
`SYKeyboard`와 키보드 extension scheme의 TestAction이 `SYKeyboardTests`를 포함한다.
