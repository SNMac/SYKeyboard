# 도메인 문서

엔지니어링 스킬이 코드베이스를 탐색할 때 이 저장소의 도메인 문서를 읽는 방법이다. 이 저장소는 **single-context**다.

## 탐색 전에 읽는 것

- 저장소 루트의 **`CONTEXT.md`**
- **`docs/adr/`**: 작업할 영역에 닿는 ADR

`CONTEXT.md`는 아직 없다. 없는 파일은 **조용히 넘어간다.** 없다고 지적하거나 미리 만들자고 제안하지 않는다. `/domain-modeling` 스킬
(`/grill-with-docs`, `/improve-codebase-architecture`에서 진입)이 용어나 결정이 실제로 정해질 때 그때그때 만든다.

이 저장소의 기존 문서는 아래와 같이 다룬다.

- `CLAUDE.md`: 에이전트 지침의 단일 기준. 구조·규칙·검증 방법이 여기 있다.
- `docs/architecture/`: 현재 아키텍처 설명(전체 아키텍처, 한글 입력, 자동완성, 삭제·실행취소, 한영 통합 키보드, 성능). 작업 영역의 문서를 읽는다.

## 파일 구조

```
/
├── CONTEXT.md
├── docs/
│   ├── adr/
│   │   ├── 0001-....md
│   │   └── 0002-....md
│   └── architecture/
├── Modules/
└── ...
```

## 용어집의 어휘를 쓴다

결과물(이슈 제목, 리팩터링 제안, 가설, 테스트 이름)에서 도메인 개념을 부를 때 `CONTEXT.md`에 정의된 용어를 쓴다.
용어집이 피하라고 한 동의어로 바꾸지 않는다.

필요한 개념이 용어집에 없다면 신호다. 프로젝트가 쓰지 않는 말을 지어내고 있거나(다시 생각한다), 실제 빈틈이 있는 것이다(`/domain-modeling`용으로 적어 둔다).

## ADR과 충돌하면 드러낸다

결과물이 기존 ADR과 어긋나면 조용히 덮어쓰지 말고 명시한다.

> _ADR-0007(…)과 어긋나지만 다시 열어 볼 만하다. 이유는…_
