# 수식 자동완성 숫자 입력과 결과 표기 확장 설계

## 배경

현재 `MathExpressionCompletionEvaluator`는 숫자, 소수점, `+`, `-`, `*`, `/`, 괄호와 공백만
수식으로 인식한다. 숫자 안의 천 단위 쉼표와 키보드에서 자주 사용하는 곱셈·나눗셈 기호는
수식 범위에서 제외되며, 결과도 천 단위 구분 없이 최대 소수 셋째 자리까지만 표시한다.

큰 정수 결과는 `Int` 범위를 벗어나면 후보를 만들지 않는다. 사용자가 입력한 수식을 그대로
표시하면서 숫자 입력 형식을 확장하고, 읽기 쉬운 일반 표기와 과학적 표기를 결과 크기에 따라
선택해야 한다.

## 확정 동작

- 숫자 안의 쉼표는 `1,000`, `12,345,678`처럼 첫 그룹 1~3자리와 이후 3자리 그룹으로 구성된
  경우에만 허용한다.
- 곱셈 연산자는 `×`, `⋅`, `*`, `x`, `X`를 인식한다.
- 나눗셈 연산자는 `÷`, `/`를 인식한다.
- 숫자가 `1.`처럼 소수점으로 끝나도 정수 `1`로 계산한다.
- `.` 단독, `1..0`, `10,00`처럼 유효하지 않은 숫자는 후보를 만들지 않는다.
- 일반 결과는 기존처럼 소수 셋째 자리까지 반올림하고 천 단위마다 `,`를 표시한다.
- 결과의 절댓값이 `10,000,000,000` 이상이면 유효숫자 4자리 과학 표기를 사용한다.
- 과학적 표기는 `1.235×10¹⁰`처럼 곱셈 기호와 위 첨자 지수를 사용한다.
- 입력 수식의 공백, 쉼표, 연산자 기호는 `displayText`에서 사용자가 입력한 그대로 유지한다.
- `insertText`에는 일반 표기 또는 과학적 표기로 포맷된 결과만 저장한다.

## 예시

| 입력 | 결과 후보 |
|---|---|
| `1,000 * 1,000=` | `1,000,000` |
| `1,000 × 2=` | `2,000` |
| `1,000 ⋅ 2=` | `2,000` |
| `1,000 x 2=` | `2,000` |
| `1,000 X 2=` | `2,000` |
| `1,000 ÷ 4=` | `250` |
| `1,000 / 4=` | `250` |
| `1.+2=` | `3` |
| `10*1234567890=` | `1.235×10¹⁰` |
| `-10*1234567890=` | `-1.235×10¹⁰` |
| `10,00+1=` | 후보 없음 |
| `.+1=` | 후보 없음 |

## 비목표

- 연산자 우선순위, 괄호 처리 또는 앞쪽 음수 허용 정책을 변경하지 않는다.
- 중간 단항 부호 입력을 새로 허용하지 않는다.
- 소수 셋째 자리 반올림 정책을 변경하지 않는다.
- 통화, 백분율, 단위 변환 또는 함수 계산을 추가하지 않는다.
- 사용자의 locale에 따라 소수점과 그룹 구분 문자를 바꾸지 않는다.
- 자동완성 후보 선택, 스페이스 확정, 수식 전체 대치 동작을 변경하지 않는다.

## 설계

### 수식 범위 추출

`expressionSuffix(beforeEqualIn:)`의 허용 문자 집합에 `,`, `×`, `⋅`, `x`, `X`, `÷`를 추가한다.
이 단계는 수식으로 볼 수 있는 마지막 연속 구간만 추출하며 숫자와 연산자의 유효성은 파서가
검증한다.

### 연산자 정규화

파서는 입력 원문을 표시용으로 변경하지 않는다. 계산용 문자 배열을 만들 때 다음 기호만
정규화한다.

```text
×, ⋅, x, X → *
÷          → /
```

공백은 기존처럼 계산용 배열에서 제거한다. `displayText`는 정규화 전 `expressionText`를 사용하므로
사용자가 입력한 기호와 쉼표가 그대로 보존된다.

### 숫자 파싱

`parseNumber()`는 정수부, 선택적 소수점, 선택적 소수부를 하나의 숫자 토큰으로 읽는다.

- 정수부에는 숫자가 최소 한 자리 있어야 한다.
- 쉼표가 없으면 기존 숫자 입력을 그대로 허용한다.
- 쉼표가 있으면 첫 그룹은 1~3자리, 이후 그룹은 정확히 3자리여야 한다.
- 소수부에는 쉼표를 허용하지 않는다.
- 소수점 뒤 숫자는 0자리 이상 허용해 `1.`을 유효하게 처리한다.
- 계산 전에 쉼표를 제거하고, 끝의 소수점은 제거한 문자열을 `Double`로 변환한다.

Foundation의 locale 기반 숫자 파싱은 잘못된 구분자가 나타났을 때 전체 문자열을 거부하지 않고
앞부분만 해석할 수 있으므로 사용하지 않는다. 파서가 토큰 전체를 직접 검증해 부분 파싱을
방지한다.

### 일반 결과 포맷

계산값은 기존처럼 소수 셋째 자리에서 반올림한다. 절댓값이 `10,000,000,000`보다 작으면
`en_US_POSIX` locale의 decimal 포맷을 사용한다.

- 그룹 구분자: `,`
- 그룹 구분 사용: 활성화
- 최소 소수 자릿수: 0
- 최대 소수 자릿수: 3

결과가 `1,000` 이상일 때만 실제 쉼표가 나타나며, 작은 결과에도 동일한 고정 포맷 정책을
적용한다.

### 과학적 결과 포맷

절댓값이 `10,000,000,000` 이상인 유한 결과는 직접 과학적 표기로 변환한다.

1. 지수는 `floor(log10(abs(value)))`로 구한다.
2. 가수는 `value / 10^exponent`로 구한다.
3. 가수를 유효숫자 4자리로 반올림한다.
4. 반올림된 가수의 절댓값이 `10`이 되면 가수를 10으로 나누고 지수를 1 증가시킨다.
5. 가수의 불필요한 끝자리 `0`과 소수점을 제거한다.
6. 지수의 숫자와 부호를 위 첨자 문자로 변환해 `가수×10지수`를 만든다.

예를 들어 `12,345,678,900`은 `1.235×10¹⁰`이 된다. 음수 부호는 가수 앞에 유지한다.
큰 유한 결과를 더 이상 `Int` 범위로 제한하지 않으며, `Double`의 무한대와 `NaN`은 계속
후보에서 제외한다.

## 오류 처리

- 유효하지 않은 쉼표 그룹, 중복 소수점, 숫자 없는 소수점은 파싱 실패로 처리한다.
- 지원하지 않는 문자나 연산자는 수식 범위 또는 전체 파싱 검증에서 제외한다.
- 0으로 나누기와 유한하지 않은 중간·최종 결과는 기존처럼 후보를 만들지 않는다.
- 마지막 `=` 외에 수식 안에 다른 `=`가 있으면 기존처럼 후보를 만들지 않는다.
- 과학적 표기 지수 변환이 실패하면 후보를 만들지 않는다.

## 테스트

Swift Testing으로 다음 동작을 RED에서 먼저 확인한다.

1. 올바른 천 단위 쉼표 입력을 계산하고 원문 쉼표를 보존한다.
2. 잘못된 쉼표 그룹과 소수부 쉼표를 거부한다.
3. `×`, `⋅`, `*`, `x`, `X`를 동일한 곱셈으로 계산한다.
4. `÷`, `/`를 동일한 나눗셈으로 계산한다.
5. 소수점으로 끝난 숫자를 계산하고 숫자 없는 소수점을 거부한다.
6. 일반 정수 결과에 천 단위 쉼표를 표시한다.
7. 일반 소수 결과에 천 단위 쉼표와 기존 최대 소수 셋째 자리 반올림을 함께 적용한다.
8. 절댓값이 `10,000,000,000` 미만이면 일반 표기를 유지한다.
9. 절댓값이 `10,000,000,000` 이상이면 유효숫자 4자리 과학 표기를 사용한다.
10. 음수 큰 결과와 가수 반올림으로 지수가 올라가는 경계를 처리한다.
11. 기존 우선순위, 괄호, 단항 부호 제한, 0 나누기 테스트가 모두 통과한다.

## 수동 검증

한글·영문 키보드를 실제 입력 앱에서 열고 다음을 확인한다.

1. 지원하는 각 곱셈·나눗셈 기호 뒤에 `=`를 입력하면 동일한 결과 후보가 표시된다.
2. 쉼표가 포함된 입력의 왼쪽 후보는 원문을 유지하고 가운데·오른쪽 후보는 포맷된 결과를 사용한다.
3. 스페이스와 후보 탭으로 일반 결과와 과학적 결과를 확정했을 때 표시 문자열이 그대로 삽입된다.
4. 잘못된 쉼표 또는 소수점 입력에는 수식 결과 후보가 표시되지 않는다.

## 완료 조건

- 확정된 숫자 입력과 연산자 기호가 모두 계산된다.
- 일반 결과는 천 단위 쉼표와 최대 소수 셋째 자리 반올림을 적용한다.
- 11자리 이상 정수부를 갖는 결과는 유효숫자 4자리 과학 표기로 표시된다.
- 입력 원문은 자동완성 후보에서 변경되지 않는다.
- 관련 evaluator 테스트, 전체 `SYKeyboard` 테스트, `HangeulKeyboard`와 `EnglishKeyboard` 빌드가
  통과한다.
