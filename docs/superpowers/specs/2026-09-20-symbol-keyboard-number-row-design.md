# 기호 자판 숫자 행과 배열 재구성 설계

## 목적

GitHub Issue #138으로 추가한 숫자 행 기능에 이어 네 가지를 바꾼다.

1. 기호 자판(기본·웹 검색)에도 숫자 행을 표시하고, 숫자가 쓰던 줄에 기호를 채운다.
2. URL·이메일 자판도 기본 기호 배열을 쓰게 한다. 스페이스 옆 키만 모드별로 남긴다.
3. 위 작업 중 확인한 기호 자판 셋째 줄 정렬 문제를 고친다.
4. 빈 키가 섞인 줄이 다른 버튼의 폭을 끌고 가지 않게 폭 기준을 바꾼다.

## 확인한 기준

- 작업 브랜치: `feat/#138-number-row`, 기준 커밋 `2c272507`.
- `2026-09-18-number-row-design.md`의 결정을 그대로 따른다. 숫자 행은 세로 46.5pt,
  가로 35pt로 두 방향 모두 표시한다.
- 기호 자판은 `SymbolKeyboardView`가 4행으로 그린다. 행별 버튼 개수는 생성 시점에
  `SymbolKeyboardMode.keyList[0][행].count`로 고정되고, 페이지 전환(`isShifted`)은
  버튼의 글자만 바꾼다. 따라서 어떤 배열이든 **10 / 10 / 5개**를 지켜야 한다.
- 글자가 빈 키(`[]`)는 `PrimaryKeyButton`이 `isHidden = true`로 접는다.
- 기본 모드와 웹 검색 모드는 `keyList`를 공유한다. 기본 모드를 바꾸면 웹 검색도 따라온다.

## 결정 사항

### 1. 기호 자판 숫자 행 (기본·웹 검색)

**적용 조건은 숫자 행 설정 ON 하나뿐이다.** 꺼져 있으면 지금 배열을 쓴다.
화면 방향은 조건이 아니다. 숫자 행은 가로에서도 보이므로 배열도 그대로 간다.

숫자 행은 두 페이지 공통이며 두벌식·쿼티와 같은 자리, 같은 높이다.
세로 46.5pt, 가로 35pt다.

배열 규칙은 **원래 숫자 밑에 있던 줄을 숫자 행 밑에 그대로 두고, 새 줄을 그 아래에
넣는 것**이다. 두 페이지 모두 같은 규칙을 따른다.

```
     1  2  3  4  5  6  7  8  9  0        ← 숫자 행 (두 페이지 공통)

1페이지                             2페이지 (⇧)
  -  /  :  ;  (  )  ₩  &  @  ”       _  \  |  ~  <  >  $  £  ¥  •
  [  ]  {  }  #  %  ^  *  +  =       ※  ☆  ★  ○  ●  □  ■  △  ▲  ♡
 ⇧    .  ,  ?  !  ’          ⌫      ⇧    .  ,  ?  !  ’          ⌫
```

셋째 줄과 넷째 줄은 지금과 같다.

새로 넣는 도형 열 개는 아래 문자를 쓴다. 빈 것 다음 채운 것 순서다.

| 문자 | 코드 포인트 | 이름 |
|---|---|---|
| `※` | U+203B | 참고표 |
| `☆` | U+2606 | 빈 별 |
| `★` | U+2605 | 채운 별 |
| `○` | U+25CB | 빈 원 |
| `●` | U+25CF | 채운 원 |
| `□` | U+25A1 | 빈 네모 |
| `■` | U+25A0 | 채운 네모 |
| `△` | U+25B3 | 빈 세모 |
| `▲` | U+25B2 | 채운 세모 |
| `♡` | U+2661 | 빈 하트 |

채운 하트 `♥`(U+2665)는 넣지 않는다.

### 2. URL·이메일 자판도 기본 배열을 쓴다

**2026-09-21 변경.** 앞선 결정(주소용 기호를 한 페이지에 모으고 전용 2페이지를 두는 것)을
철회한다. 네 모드가 **같은 기호 배열**을 쓴다.

근거는 iOS 시스템 키보드 관찰이다. iOS 18.6 시뮬레이터는 URL·이메일에 전용 기호 자판을
내주지만, **iOS 27 실기기는 webSearch를 뺀 모든 타입에 기본 기호 자판을 낸다.** 애플이
바꾼 방향을 따른다.

전용 배열을 버려도 잃는 것이 적다. 주소 입력에 필요한 `@` `/` `:` `-` `_` `~`가 기본
배열에 이미 다 있다. 대신 사용자가 외울 배열이 하나로 줄고 모드별 분기가 사라진다.

```
1페이지  -  /  :  ;  (  )  ₩  &  @  ”
        [  ]  {  }  #  %  ^  *  +  =
2페이지  _  \  |  ~  <  >  $  £  ¥  •
        ※  ☆  ★  ○  ●  □  ■  △  ▲  ♡
```

도형 열 개는 기본 2페이지에 있으므로 URL·이메일에서도 그대로 쓸 수 있다.

**스페이스 옆 키는 모드별로 그대로 둔다.** URL의 `.` `/` `.com`, 이메일의 `@` `.`,
웹 검색의 `.`이다. iOS 27은 webSearch 말고는 이것도 없앤 것으로 보이지만 따르지 않는다.
`.com` 하나가 네 번 누를 것을 한 번으로 줄이고, 기호 자판에 들어갈 필요 자체를 없앤다.
기호 배열 통일과는 성격이 다른 편의 기능이다.

`SymbolKeyboardMode`는 이제 **스페이스 옆 키 구성만** 가른다. 기호 배열은 모드와
무관하므로 `keyList(usesNumberRow:)`는 `static`으로 둔다.

### 3. 기호 자판 셋째 줄 정렬 수정

이 문제는 숫자 행과 무관하게 지금도 있다. URL·이메일 자판의 셋째 줄이 오른쪽으로
몰려 보인다.

원인은 `SymbolKeyboardView.swift:206-207`이다. 셋째 줄 첫 버튼의 너비를 **맨 마지막
버튼**의 너비에 묶어 둔다.

```swift
guard let lastButton = thirdRowPrimaryKeyButtonList.last else { ... }
button.widthAnchor.constraint(equalTo: lastButton.widthAnchor).isActive = true
```

URL·이메일은 셋째 줄이 `. _ - +` 네 개에 마지막 한 칸이 빈 키다. 그 버튼이 숨겨져
너비가 0이 되면서 거기에 묶인 첫 버튼도 0이 된다. 원래 첫 버튼과 마지막 버튼이 양
끝에서 남는 폭을 나눠 갖는 구조인데, 그게 무너져 남는 폭이 전부 왼쪽에 쏠린다.
기본 모드는 `. , ? ! ’` 다섯 개가 다 차 있어 드러나지 않는다.

**빈 키를 뺀 실제 키 중에서 첫 키와 마지막 키를 정한다.** 그러면 몇 개가 비든 남는
폭이 양 끝으로 고르게 갈라진다. 이 수정은 숫자 행 설정과 무관하게 항상 적용한다.

2번 결정을 바꾼 뒤로는 네 모드가 모두 셋째 줄이 다 찬 기본 배열을 쓰므로 이 증상이
실제로 드러나지는 않는다. 그래도 수정은 유지한다. "모든 줄이 우연히 꽉 차 있다"는
전제에 기대지 않게 하는 것이 이 변경의 값어치다.

### 4. 버튼 폭 기준을 줄 너비로 바꾸기

`⇧`, `⌫`, 한영 전환, 자판 전환, 지구본 버튼의 너비는 **첫 줄 첫 번째 키**를 기준으로
계산한다. 예를 들어 삭제 버튼은 첫 줄 키의 1.35배다.

첫 줄에 빈 키가 섞이면 이 기준이 무너진다. 빈 키는 숨겨져 스택 계산에서 빠지므로,
열 칸 중 여덟 개만 보이면 그 여덟 개가 줄 너비를 8등분한다. 기준 키가 1/10에서 1/8로
커지고 거기 묶인 버튼이 전부 25% 커진다. 실제로 잠시 존재했던 합친 URL 배열에서
iPhone 13 mini 세로 기준 삭제 버튼이 50.6pt 대신 63.3pt로 측정됐다. 자판 전환 버튼의
배율은 "한 줄에 10칸"을 전제로 계산하는데 실제 기준 키가 1/8이라 전제와도 어긋났다.

2번 결정을 바꾼 뒤로는 네 모드가 모두 첫 줄이 다 찬 기본 배열을 쓰므로 이 증상이
실제로 드러나지는 않는다. 그래도 수정은 유지한다. 셋째 줄 정렬과 같은 이유다.

**줄마다 키 개수가 다른 것 자체는 그대로 둔다.** iOS 기본 이메일 자판도 숫자 열 칸
아래에 여덟 칸을 넓게 퍼뜨린다. 바꾸는 것은 폭을 재는 기준뿐이다.

**기준을 "보이는 키 하나"가 아니라 "줄 너비의 1/10"로 바꾼다.** 그러면 몇 칸이 비든
버튼 폭이 흔들리지 않는다. 같은 파일의 셋째 줄이 이미 이 방식이다. 줄 스택 너비에
`1.0 / 배열 개수`를 곱하므로 빈 칸이 생겨도 폭이 유지된다.

### 배열이 정해지는 시점

기호 자판 배열은 **숫자 행 설정에만** 의존한다. 화면 방향은 상관없다. 숫자 행이 두
방향 모두 보이므로, 돌린다고 기호 자판에서 숫자를 칠 수 없게 되는 일이 없다.

따라서 배열은 뷰를 만들 때 한 번 정해지고 회전해도 바뀌지 않는다. 회전 시 달라지는
것은 숫자 행 높이(46.5pt ↔ 35pt)뿐이다.

## 범위 밖

- 나랏글·천지인 숫자 행
- URL·이메일에 남는 빈칸 채우기
- 숫자 행 높이 사용자 설정
- 숫자 키의 길게 누르기 기호 입력

## 알려진 제약

새 도형 열 개는 **숫자 행을 켠 사용자에게만** 보인다. 설정이 꺼져 있으면 기호 자판이
지금 배열이라 도형 줄이 없다. 숫자 행을 켠 사용자에게 주는 덤으로 두기로 했다.

## 테스트

- 기호 자판 배열 선택 규칙: 모드(기본·웹 검색·URL·이메일) × 숫자 행 ON/OFF 조합별로
  각 행의 정확한 문자 목록을 검증한다. 모든 조합이 10/10/5개를 유지하는지도 함께 본다.
- 셋째 줄 정렬: 빈 키가 섞인 줄에서 첫 키와 마지막 키의 기준이 실제 키로 잡히는지
  정책 수준에서 검증한다.
- 빌드: `SYKeyboard`, `HangeulKeyboard`, `EnglishKeyboard`, `HangeulEnglishKeyboard`
  scheme을 `iPhone 13 mini / iOS 18.6`에서 빌드한다.
- 버튼 폭 기준: 첫 줄에 빈 키가 섞여도 `⇧`·`⌫`와 넷째 줄 묶음의 폭이 10칸 기준으로
  유지되는지 검증한다.
- 기호 배열이 모드와 무관함: 네 모드가 같은 배열을 돌려주는지 검증한다.
- 수동: 실제 입력 앱에서 기호 자판의 숫자 행, 두 페이지 배열, 셋째 줄 정렬, 숫자 키가
  실제로 입력되는지를 확인한다. URL·이메일에서 기호 배열이 기본과 같고 스페이스 옆 키만
  다른지, 가로로 돌렸을 때도 숫자 행과 같은 배열이 유지되는지 함께 본다.
