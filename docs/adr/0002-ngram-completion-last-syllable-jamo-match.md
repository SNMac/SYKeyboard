# 입력 중 NGram 완성은 마지막 글자만 자모로 비교하고 자판별 중간 상태는 보정하지 않는다

입력 중 NGram 단어 완성(#158)은 `SuggestionController` 공통 경로에서 자판을 모른 채 판정한다
(`PredictiveTextCompletionMatchPolicy`). 원칙은 "보이던 목표 후보는 사용자가 그 단어를 계속 입력하는 동안 사라지지
않는다"이고, 세 자판 공통으로 이를 깨는 경우는 마지막 글자의 받침이 사실 다음 글자의 초성인 경우('키보' → `"키볻"`,
'달' → `"닭"`)다. 그래서 입력의 **마지막 글자만** 호환 자모로 나눠 비교하고 **겹받침은 두 자음으로** 나눈다.
**모음 합성(ㅘ, ㅐ)과 쌍자음은 나누지 않는다.** 합성 전 상태('고')에서는 목표('과자')가 아직 보이지 않았으므로 원칙을
깨지 않고, 나누면 두벌식에서 '가'에 '개발'이 뜨는 잡음이 생기기 때문이다. 천지인의 끝에 붙은 조합 중 모음
(`ㆍ`, `ᆢ`)은 떼고 비교한다.

## 알려진 한계

실제 처리기(`DubeolsikProcessor`·`NaratgeulProcessor`·`CheonjiinProcessor`)로 키 입력마다 판정한 결과다
(T = 목표를 완성 후보로 봄, 마지막 칸은 입력이 목표와 같아 F). 굵은 F가 목표가 한 타 동안 빠지는 상태다.
`HangeulCompletionMatchScenarioTests`가 이 표를 고정한다.

| 자판 | 목표 | 키 입력별 상태 |
| --- | --- | --- |
| 두벌식 | 키보드 | ㅋ:T 키:T 킵:T 키보:T 키볻:T 키보드:F |
| 두벌식 | 달걀 | ㄷ:T 다:T 달:T 닭:T 달갸:T 달걀:F |
| 두벌식 | 안주 | ㅇ:T 아:T 안:T 앉:T 안주:F |
| 나랏글 | 키보드 | ㄱ:F ㅋ:T 키:T **킴:F** 킵:T 키보:T **키본:F** 키볻:T 키보드:F |
| 나랏글 | 달걀 | ㄴ:F ㄷ:T 다:T 달:T 닭:T **달가:F** 달갸:T 달걀:F |
| 나랏글 | 안주 | ㅇ:T 아:T 안:T **안ㅅ:F** 앉:T 안주:F |
| 천지인 | 키보드 | ㄱ:F ㅋ:T 키:T 킵:T 킵ㆍ:T 키보:T 키볻:T 키보드:F |
| 천지인 | 달걀 | ㄷ:T **디:F** 다:T **단:F** 달:T 닭:T **달기:F 달가:F** 달갸:T **달갼:F** 달걀:F |
| 천지인 | 안주 | ㅇ:T **이:F** 아:T 안:T 앉:T **안즈:F** 안주:F |

나랏글 획추가·쌍자음 전 상태('킴' → '킵'), 천지인 모음 조합 전 상태('디' → '다')와 자음 순환 전 상태('단' → '달')다.
자판 규칙을 모르는 `SuggestionController`에서는 풀지 않는다. 같은 구간에서 `UITextChecker` 후보도 같은 방식으로 바뀐다.
같은 이유로 자모 분해도 `HangeulKeyboardCore`의 오토마타 함수를 쓰지 않고 정책 안에 따로 둔다. 의존 방향이
`HangeulKeyboardCore` → `SYKeyboardCore`라 반대로 부를 수 없다.
